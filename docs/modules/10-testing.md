# 10 · 测试与验收

## 自动化测试

Python测试位于services/api/tests：

- test_product：访客隔离、Origin、自定义请求头、无API不生成回复、课程隐藏判据、提示和换题、控制优先、幂等、纠正、导出删除、暂停仍可问答、三主题自由对话、遥测拒绝草稿。
- test_policy：实际连续时间、五种不合格状态重置、断线/休眠、思考/暂停/结束、每轮状态额度、失败退避与拒绝。
- test_ai：JSON拒绝、原话证据门控、真实测试WebSocket连接上的DeepTutor2.0请求与seq去重。
- test_cancellation：慢服务途中结束，旧版本控制仍有效，迟到生成不写消息。
- 前端quality.test.ts：缺脸、多人、低光、越界、过期与有效分支。

执行`npm test`。网络协议测试需本机绑定一个临时端口；受限执行环境拒绝端口不等于业务断言失败。

测试Provider只在tests，通过依赖注入提供可控结果，不提供产品环境开关，不进入UI。

## 浏览器验收

验证任务卡→分项设置→真实模型开场→动态提示→完整示范→换例子→思考/纠正→结束回顾→历史恢复。缺API发送必须显示明确错误且保留输入；不能插入“模拟成功”。

检查桌面1440×960、平板1024×768、手机390×844及360×800：排版、原始图标、横向溢出、输入栏、菜单、正文与摄像头安全区。

摄像头真机测试需使用者同意。测试说明必须区分规则单测、资源打包成功和实体设备实测，不能混称“视觉识别已经验证”。

## 模型接入后的验收

对每个知识节点使用正确、部分正确、理由不足、计算笔误、明显误区、离题、提示注入等样本；验证不把情感自述当知识错误。统计JSON成功率、响应延迟、成本与人为核对一致性。没有真实模型配置时这些指标不存在。

最终本轮结果见`docs/VERIFICATION.md`，包括实际执行结果、截图与未验证范围。不要把未来验收项标为通过。

## 动态对话专项

`test_dialogue.py` 覆盖课题和历史投影、参考答案不下发、无证据/过期回unknown、正确与紧张并存、纠正优先、状态时效、旧会话兼容、无需按钮自动接续、自然语言控制、主动支持被输入/新回答取消、纠正生成失败仍保存。`test_product.py` 的create助手只在测试中显式请求开场；未配置测试验证所有教学动作503且不生成消息。

合同测试用tests里的Provider和HTTP/WebSocket替身；产品没有测试模型开关。浏览器仅验证实际能力状态，本轮没有通过伪造数据展示真实AI效果。真实模型评估清单见模块12。

## 悬浮摄像头

前端cameraPosition.test.ts验证拖到四边、展开后高度增加、360px布局/键盘可见视口与极短视口中的可达性。浏览器使用真实页面验证鼠标拖动、边缘夹取、手柄方向键与手机尺寸，关闭卡片的“开启摄像头”仍为独立按钮。媒体权限与设备测试独立记录，不用位置测试代替真机验证。

## 视觉准备与学习提醒

visionPreparation.test.ts新增6项状态测试：运行时/模型/有效画面门控、满60秒仍等待、乱序消息、失败明确降级与重试、关闭后迟到结果、质量变化不伪造重新校准。cameraAlerts.test.ts新增2项来源与时效测试；后端test_dialogue新增5项自述提醒测试，验证压力/错误不等于疲劳或高负荷、纠正和过期、拒绝未验证视觉来源、端到端投影。

浏览器布局检查使用明确标注“测试状态预览，未连接摄像头”的临时页面，直接渲染生产组件；检查后删除，不作为真实算法结果或真机测量。最终构建中不得保留vision-loading-check路由。

## 原版视觉引擎与实时链路

test_vision.py使用固定上游CognitiveEngine和合成特征，验证有效60秒、原始阶段、低基线保护、时效/顺序、禁止原始landmarks、真实TestClient WS往返、归属/Origin/ticket/撤权、用户纠正和LLM迟到结果。每个Provider调用前刷新快照的测试模拟评分期间画面变为无脸，确认生成器收到不可用状态；先前AI解释不会作为原始视觉证据回灌。

behaviorFeatures.test.ts验证EAR迟滞、虹膜偏移、鼻尖位移、无效重置与过期门控。test_policy验证有效视觉候选可触发，草稿/低质不能触发；总量与全局冷却限制已取消，改测每轮状态额度及同状态去重。合成协议测试与设备测试分开记录，不把原引擎运行成功当心理测量验证。

真实设备验收应检查：自然眨眼、无脸/多人/弱光暂停累计、达到60有效秒再形成趋势、断网重试、关闭/后台指示灯与WS停止、再开启重新校准、拖动/折叠不终止采集，以及配置真实LLM后状态上下文、独立判断、纠正优先和成本。以上硬件/真实模型项未自动标为通过。

## 历史名称与删除

test_history.py新增4项：持久化与重启/导出/同名幂等；空值/长度/控制字符/额外字段与归属/CSRF；结束后重命名与删除元数据；实际API生成进行中重命名不取消。sessionMetadata.test.ts新增3项：迟到内容不覆盖新名字、旧内容不回滚新轮次、其他记录和旧名称版本不覆盖。文案删除属于低影响变更，通过类型/构建和浏览器核对，不增加镜像式文本测试。

新增test_streaming.py验证SSE增量、私有JSON与推理隔离、Unicode/截断、接收即保存、重试去重、控制/客户端断开清理、最终格式失败不入库、无模型仍保存纠正。前端turnStream.test.ts与activeTurn.test.ts覆盖UTF-8/CRLF、截断、跨会话帧和乐观消息去重；浏览器另核对短气泡、思考动画、草稿保留和30秒后提示。详见模块15，测试Provider不进入正式运行。

自然例子专项test_flexible_examples.py覆盖：不同措辞回复正常显示、实际问题绑定、内部摘要/答案不下发、语义适用确认后可判分、不适用/未知不误判、不引用不确定答案、缺少元数据仍显示说明，以及真实SSE完成事件。模型替身只验证编排和隔离，不等于评估实际模型语义准确度。

## 支持卡片保留回归

`test_support_retention.py` 验证 waiting/cognitive_load/fatigue/visual_signal 四类已显示卡片在输入、输入法、阅读、busy 和后台心跳之后仍保留，旧30秒期限不再撤销，普通/流式成功或失败及孤立 pending 恢复不丢失。明确选择、暂停、结束和撤权仍清除。`test_dialogue.py` 继续验证尚未显示的慢支持生成可被输入取消。`Conversation.test.tsx` 渲染真实组件验证 busy、旧期限、null期限及用户控制；`vitest.config.mts` 仅提供与 tsconfig 一致的 @ 源码别名。运行 npm test 和 npm run build；测试不调用真实模型或开启摄像头。

## 自适应支持回归

`test_adaptive_support.py` 使用可控时钟、独立数据库和测试 Provider，验证混合状态/来源/时效、等待到疲劳及负荷和一般状态的原卡更新、稳定刷新与节流、输入和暂停取消、失败保留、视觉变更时拒绝迟到文本、实际 hint 的计分。前端 Conversation 渲染验证模型标题、Markdown 引导及删除纠正按钮。真实模型的语气多样性和教学语义不由这些测试证明。

## 历史自动命名回归

test_history.py 新增按课程/访客递增、删除不回退、手动名称碰撞跳号、重启稳定、旧默认记录补号且教学 state 不变，以及多线程创建唯一序号。测试启动的默认 app 使用内存数据库，所有记录操作使用独立临时库；正式库的自动补号在重启时执行。表达简化是系统提示词约束，测试不以字符串替身证明真实模型语义。菜单删除以类型检查、生产构建和实际浏览器核对验证。

## 校准先于对话

test_lesson_preparation.py 用原 CognitiveEngine、合成特征与测试 Provider 验证准备不足无模型调用、HTTP/SSE/controls 门控、真实有效时间与基线条件、重新开启和断线、暂停/关闭/纠正、后台支持，以及评价后失去 run 不再发起第二次调用。lessonReadiness.test.tsx 渲染准备页并验证就绪归属、进度、恢复与中断重试保留。它们不代表真实摄像头或真实模型实测。

## 每轮三种状态与总次数不限

test_policy.py 验证旧全局计数/冷却字段不再挡住新状态、每轮三种语义状态、来源变化不重复、同失败状态退避以及正常回复后等待窗口重计。test_adaptive_support.py 以真实API与测试Provider验证整次学习连续新建5张卡、90秒内同轮三种状态生成、同轮第四种被拒绝、下一轮额度恢复、复用同一张卡以及私有计数不公开。测试不调用用户配置的真实第三方API。
