# 05 · 自适应支持卡片

## 职责与修改入口

- `study/support.py`：从当前有效证据选择支持需求，合并理解卡点、认知负荷和疲劳，保留来源；不包含任何用户可见话术。
- `study/policy.py`：首次触发、冷却/去重、状态稳定窗口与刷新频率。
- `study/ai.py`：通过真实 Provider 生成标题及正文；系统角色为“AI 学习智能伴侣”。
- `study/main.py`：后台生成、原卡更新、归属/版本/时效校验、取消与提示计分。
- `study/learning.py`：用户选择、普通消息提交和 episode 公共投影。
- `Conversation.tsx`：显示生成标题与 Markdown 支持文字，保留 Figma 的浅绿卡片和响应式 actions 样式。

修改状态判断只改 support.py，修改门控/节流只改 policy.py/config.py，修改表达只改 REPLY_SYSTEM，修改 UI 只改 Conversation。页面不读取原始特征或选择固定台词，不直连模型，也不接触密钥。

## 首次触发

必须已有完成的助手回复，active、support 已授权且开启，无 pending/保护/已有 episode，版本一致、前台、无草稿/输入法组合/生成/阅读。满足任一条件后才启动真实生成：

- 连续30秒有效等待；最长心跳间隔8秒，输入、阅读、后台或断线重置。没有待作答练习也可等待。
- 有效自述/纠正明确存在认知负荷或疲劳。
- 当前有效的理解困难：明确自述，或由实际可见问题的可靠作答评价形成的 task_answer 证据。
- 已校准、当前有效的 possible_overload / possible_fatigue 视觉候选。

支持将“认知障碍”按学习场景理解为当前卡点，不作疾病或能力诊断。单独的错误次数、压力、普通回复、未知或过期状态不触发。整次学习没有卡片总量限制，也没有90秒全局冷却。首次生成与原卡重写共享每轮最多3次不同状态内容的额度；同轮同状态不重复生成，下一轮重置。思考保护和明确拒绝仍优先。求助文字和手动提示直接回应，无需等待门槛。

## 自适应内容与来源

support_context 返回 kind 和 signals。kind 为 difficulty / cognitive_load / fatigue / waiting / general；signals 保留来源、用户已提交的证据和 tentative 标志。自述/纠正优先于同维度视觉线索；“我不累/负担可以接受”抑制相应视觉提示。自述沿用300秒且不超过3轮时效；失效或未知不沿用旧判断。视觉仅提供疲劳/负荷候选，不判定知识理解或情绪。

混合状态保留全部有效需求；先关照精力，再考虑信息量和具体卡点。等待本身不能推断疲劳、过载或挫败。模型接收 proactive_context、近期课内对话、当前公开问题、实时 visual_observation 和 previous_support，生成可选 support_title 与 reply。表达按“自然回应状态 → 有温度的理解与支持 → 一个具体小建议或引导”展开，句式和语态自由变化，不维护模板库，不机械复读旧卡。

仅有视觉线索时，首句可以自然表述检测到一些可能的疲劳/负荷迹象，保持暂定含义。明确自述时自然承接用户原话；一般状态或证据过期时不继续声称检测到疲劳。理解卡点给小切入点，负荷高减少同时处理的信息，疲劳时建议可拒绝的放慢或短暂休息，等待时留思考空间。首句和建议仍由真实模型生成，不提供备用假回复。

允许支持卡直接给一个课内小线索（assistance=hint），计入当前练习的 hint_level，后续不能算独立完成。休息、节奏和非解题建议用 none。只能 keep 当前问题，不布置新题、不公布完整答案、不自动结束或强制休息；完整示范仍需用户明确请求。模型教学准确性、同理心与语义符合度需要真实服务商人工评估。

## 保留与刷新生命周期

首次生成时 episode.text=null。活动请求立即返回，尚未显示的生成可以被输入/阅读/后台/busy 取消，也可被普通消息抢占；展示前检查归属、版本、pending、active、授权、保护及最近8秒心跳。

生成成功后 expires_at=null，卡片保留到用户处理。输入、输入法、阅读、后台、普通发送、回复中或回复失败都不删除已显示卡片。刷新页面可恢复，旧数字期限不再自动隐藏。输入只会取消未完成的重写，保留已显示的标题和正文。

有效状态变化时，可以在原 episode.id 上更新，不新增可见卡片。刷新沿用前台/无草稿/无生成/授权条件和默认6秒稳定检测，新状态不再等待30秒全局间隔。首次生成和重写均计入本轮的3次额度；CLI微小波动和来源变化不算新状态。后台生成期间保留原文，成功后整体替换标题与正文，不闪烁。

调用前和提交前再次检查本轮额度、状态去重、有效状态与模型实际输入；视觉已变化、自述失效、版本更新或控制取消则丢弃迟到结果。失败/取消不消耗成功生成额度，保留旧卡；同一失败状态重试默认间隔30秒，其他新状态不受该间隔影响。没有备用台词。等待及 general 恢复文字也计入本轮3次；额度用完保留原卡，下一次正常回复后恢复额度。保留旧卡只表示建议仍可参考，不表示旧状态持续存在。

卡片保留“我还在思考”“需要一点帮助”“暂时不用”三个操作，已删除“纠正我的理解”按钮。自然语言纠正与原后端控制接口仍可用。选择卡片操作、明确教学动作、暂停/结束/同意设置控制按原逻辑清除；暂停和拒绝可打断后台刷新。回复生成时“需要一点帮助”暂不可重复生成。

## 每轮额度的定义与存储

一轮以服务端 dialogue_turn 为准：一次正常 AI 对话回复提交后进入新轮，开场和用户手动请求的提示/示范等正常回复也会推进；自动支持生成/刷新不推进轮次，不能借刷新自行重置额度。普通发送接收但尚未完成回复时不会重置。下一次正常回复完成后，即使仍在同一道题，也重新有3次不同状态内容额度。

support_state_key 只按有效状态种类集合去重，不包括视觉分数、来源、引文措辞或问题ID。疲劳、负荷偏高、理解卡点各可形成不同内容；混合状态组合也算一种不同状态。waiting 和 general 同样各算一种内容。单轮达到3次后不再自动请求第4次，已显示卡片继续保留。

私有 support_round={turn,states,attempts} 惰性存入既有会话JSON；states仅记录本轮成功提交的语义状态，attempts记录失败/取消后的同状态重试时间。首次生成和同一张卡重写共用它。旧 episodes_count/last_support_at 仅保留历史统计，不设总量门槛；旧 prompted_evidence_keys 不再阻止新轮。support_round和generated_turn不进入public session或公共导出。原有并发版本和单pending检查保持有效。

## API、配置与隐私

`POST /api/sessions/{sid}/activity` 请求合同不变，useActivity 每2秒发送版本和布尔标志，不上传草稿。公开 episode 只含 id、question_key、reason、kind、title、created_at、expires_at、text；title/kind 对旧记录可缺省，title 可为空并使用普通 UI 标题“按你的节奏来”。reason 保留首次触发原因，当前展示类别用 kind。内部 pending_context、context_key、刷新尝试时间及证据不投影到浏览器。

当前配置：SUPPORT_MAX_STATES_PER_TURN=3（允许1–3）、SUPPORT_STATE_STABLE_SECONDS=6、SUPPORT_RETRY_SECONDS=30，位于 config.py 与 .env.example。旧 SUPPORT_MAX_EPISODES / SUPPORT_COOLDOWN_SECONDS / SUPPORT_REFRESH_SECONDS 仅保留配置兼容，不再影响触发；不修改用户现有 .env。无新依赖或数据库迁移。每次成功内容仍来自真实模型，不按视觉帧请求；视觉和自述的有效期不因卡片保留而延长。

## 验证

运行 npm test、npm run build。test_adaptive_support.py 验证混合需求、纠正优先、过期/未知、稳定窗口、同状态不重复、原卡等待→疲劳→负荷→一般支持、输入/暂停/失败保留、视觉迟到结果丢弃、hint 计分和私有字段隔离。test_support_retention.py 保留活动/普通流式消息/旧期限/恢复与明确操作回归；test_dialogue.py 保留初次慢生成被输入取消及手动抢占测试。Conversation.test.tsx 渲染真实组件检查生成标题、Markdown、删除按钮、busy 和旧期限后保留。

自动化只使用 tests 内 Provider 和临时数据库，不调用用户真实第三方服务或开启摄像头。真实表达多样性、情感体验、建议准确性、视觉效度、延迟与费用需按实际模型人工评估。

可见表达补充：状态首句保持简短暂定，不主动说眨眼、视线偏移、基线或具体推断过程，也不机械附加方法免责声明；后面的情感支持与可执行引导保持具体。内部来源、时效、签名和 reason 继续用于判断，只有用户主动问依据才简洁解释。普通回复也使用同一表达规则，详见模块04。
