# 16 · 先校准，再进入 AI 对话

## 当前流程

选择课程 → 确认监测方式。camera=false 直接进入文字学习；camera=true 时先显示准备页，立即请求摄像头、加载 Worker、建立视觉 WS 并开始实际有效采样。完成约60秒个人基线且 baseline_quality=adequate 后，自动切换到对话；空会话此时才请求真实 AI 开场。

准备页不渲染练习、对话、输入栏或手动提示。显示本机原引擎的有效采样进度，而非墙钟倒计时。无脸、低光、多脸、画面过期或间隔过长时暂停累计。资源加载/权限等待不算入60秒，基线不足不能只凭 calibrated=true 放行。

同一 run 完成基线后，暂时画面不佳只会使视觉状态未知，不会反复把用户送回准备页。关闭、断开、后台停采、重新开启或服务重启使当前 run 失效；再次开启时先重新准备。文字学习本身不需要校准。

## 文件与边界

- `features/learning/lessonReadiness.ts`：纯就绪判断及重新校准时的发送状态保留。
- `LessonPreparation.tsx`：准备页、有效秒数、错误与重试/关闭入口。
- `app/page.tsx`：协调准备页与对话，开场只在准备通过后触发，等待门控同时暂停；草稿保留。
- `features/vision/CameraPreview.tsx`：向父级报告 session/live/device/connection/observation；统一重试与立即关闭采集。
- `useVisualAnalysis.ts`：WS 状态附带会话及重试代号，旧 run 结果不能解锁新会话。
- `study/vision.py`：dialogue_ready / require_dialogue_ready，后端权威基线检查。
- `study/main.py`：HTTP/SSE/后台支持准备检查、错误409、取消与最终提交检查。
- `study/ai.py`：可选 before_request 回调，在内部评价及回复生成前各自检查准备状态。

前端仅用于流程呈现；服务端不接受客户端上传“校准完成”标记。原视频/关键点仍留浏览器，派生特征到原 CognitiveEngine，后续真实模型仍读取实时状态摘要。

## 就绪、请求与取消

前端要求当前 session、live、connected、无资源错误，且观察 calibrated=true、baseline_quality=adequate。hook 给结果附加 sessionId/restartKey，停止时立即报告未就绪；旧会话/旧重试结果无法跳过准备。

后端对 camera=true 的新模型请求要求该 owner/session/consent 对应 run 存在，且已建立充分基线。准备不足时 /turns、/turns/stream、模型教学 controls 返回409，detail 为尚未完成校准；初始拒绝不保存普通回答或启动模型。已成功请求的幂等重放仍可读取结果。

每次 Provider 调用前再次检查；评价过程中 run 丢失时，不再发起第二次回复生成。提交及 SSE delta 也检查就绪状态，迟到结果不能越过准备阶段。已 accepted 的用户文字保留，前端记录同一 request_id/message_id 的重试；准备完成后可重新生成，不重复保存用户消息。草稿也不会被清空。

校准期间后台支持不触发，等待计时重置。结束/暂停/撤权优先控制照常可用；明确纠正仍可保存，准备不足时不额外调用模型承接。camera=false 时原有文字学习和暂停后文字对话保持可用。

## UI 与设备生命周期

准备页复用 readable、stack、浅绿 support token、边框、按钮和现有响应式排版。正文最大宽度560px，顶部156px留给默认悬浮预览；没有新增断点。仍可拖动、折叠摄像头。相位切换时 CameraPreview 保持同一组件实例，不卸载或重新建立 run，防止校准完成后又重头开始。

页面重试由 retrySignal 触发同一摄像头重试，重新建立 run；关闭由 closeSignal 进入组件原 close 路径，先停 tracks/Worker/WS，再保存 camera=false，随后进入文字学习。信号使用初始值引用，新挂载不会重放前一次关闭。权限拒绝、加载失败、连接错误或基线不足显示恢复入口，用户可以显式关闭摄像头继续。

## 配置、存储与校准基线复用

无新增环境变量、依赖或数据库迁移。60秒沿用原引擎和质量规则，不能为了缩短准备伪造完成。

个人基线复用在技术上可行：可保存 baseline_blink、baseline_gaze、baseline_jitter 与设备/版本/建立时间等少量参考数据，下次先做短时有效画面复核，符合条件才恢复基线，否则重新校准。这里复用的是个人参考值，不需要保存人脸照片或视频，也不能用一张照片替代动态行为基线。

本轮尚未实现持久基线或跨会话复用，仍保留原有 run 结束清理。后续实现需要明确访客/账号绑定、授权与删除入口、设备/光照或姿态变化、有效期与漂移判据、版本兼容，以及短时复核的实际效果；不能承诺一次校准永久有效，也不应只把原引擎 calibrating 标志关掉。当前匿名Cookie不支持跨设备识别人。

## 验证与限制

npm test、npm run build。test_lesson_preparation.py 用原引擎与合成特征覆盖：三个生成入口及普通/流式请求校准前拒绝；墙钟不能放行；121个0.5秒有效采样包后可开场；无效基线拒绝；同 run 暂时无脸不重复拦截；重开/断线重新门控；关闭后文字继续；后台支持不触发；优先控制/纠正保存；评价后失去 run 不再请求第二次模型。

lessonReadiness.test.tsx 覆盖会话归属、连接/资源/基线条件、准备页进度与恢复、无输入栏，以及中断后文字和重试标识保留。自动化不打开真实摄像头、不调用真实模型；不同设备的权限、加载延迟、60秒采样体验和基线有效性仍需实体设备实测。

补充验证：自然语言暂停/结束若已在内部评价中识别，即使摄像头随后断开也按优先控制执行，不受回复提交的准备检查阻断。已用专门测试覆盖。静态组件预览在1414×827及360×800检查，手机无横向溢出，默认摄像头与标题/进度/操作区不重叠；预览明确标注合成24秒，无摄像头采集或AI调用，临时渲染脚本、预览标签页和HTTP服务已清理，视口已恢复。
