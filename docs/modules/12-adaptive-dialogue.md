# 12 · 课程内自适应对话

## 目的

将“固定题库台词+单轮回答”改成真实模型驱动的课内自由对话。用户最新要求优先于PRD中的研究实验脚本；保留PRD的事实/情绪分离、自述优先、未知、用户控制和主动支持门控，不实现受控实验的固定话术条件。

依据：用户PRD《面向学习停滞的 AI 认知与情绪主动支持产品需求文档》V0.3，2026-10-29重新读取了“反馈策略与用户回应”等相关内容。文档URL：https://my.feishu.cn/docx/IrhHd2P3BoMCcAxI40wc7ZaVnUV 。示例话术不进入产品固定回复库。

## 文件与依赖

- `courses.py`：课程scope、objectives、knowledge和误区集合。
- `dialogue.py`：history_for、ground_assessment、learner_state、response_policy、generation_context。
- `ai.py`：ASSESS_SYSTEM/REPLY_SYSTEM和两阶段模型编排。
- `support.py`：有效支持需求、混合状态、自述优先与上下文签名；详见模块05。
- `contracts.py`：TurnAssessment、StateClaim、DialogueReply、Exercise。
- `learning.py`：提交已验证结果、提示记录、纠正与兼容。
- `main.py`：鉴权、幂等、版本、取消、后台支持。

依赖方向：课程/合同 → 证据与策略 → TeachingService → API编排。UI不解析心理状态，也不挑选情感话术。

## 数据流

1. 当前选择锁定task_id；服务端取课程范围，不接受前端上传系统提示词或评分依据。
2. 本轮文字与近期可见消息送评估器。内部结果包括认知判据、意图、认知/效价/压力及疲劳/信息负荷自述和逐字证据。
3. 非本轮引文、无练习的对错结果、课程外误区标签降为unknown或空。引文检查是最低保障，不是语义认证。
4. 当前自述/纠正优先。旧自述最多保留300秒且不超过3个后续生成轮；过期回unknown。纠正使旧状态失效；新的任务证据替换旧任务困难判断，不把长期标签贴在用户身上。
5. 响应策略给模型表达约束：事实不因感受改变、困难/压力时减少信息量、未知不安慰、不贴标签、思考时不追问、明确要示范才允许完整答案。
6. 模型在课题内自然生成内容和下一步。新题私有判据与可见题干一起返回，但只有reply下发；新题以用户实际看见的回复为准，允许不同措辞和概括，不要求内部prompt逐字出现在回复中。
7. 版本检查通过才提交。主动支持生成额外检查授权、活动和状态时效；已显示的支持卡保留到用户处理，不因输入或普通回复清除，见模块05。

## 状态含义

| 维度 | 值与依据 | 限制 |
|---|---|---|
| cognition | difficulty / no_clear_difficulty / unknown；本轮明确自述或当前回答 | 单次回答不等于整体掌握 |
| valence | positive / neutral / negative / unknown；明确的当前自身自述 | “还行吧”等歧义应unknown，不能从答错推出负面 |
| pressure | low / medium / high / unknown；明确自述 | 不从表情、等待或正确率推出压力 |
| correction | 按钮纠正或本轮纠正引文 | 优先接纳，不与用户争辩，不覆盖历史判断 |

原仓库视觉行为引擎已接入，payload.visual_observation包含来源、采集时间、质量、有效性、基线、阶段和比值；每次模型调用前读取当前快照。它是辅助行为线索，不会写成自述或自动改变知识评分。视觉/声学情绪仍标为unavailable，不能把画面质量或头部位移当心理压力。详见模块13。

## 自然对话原则

对外角色统一为“AI 学习智能伴侣”，由 `ai.py` 的 `REPLY_SYSTEM` 定义，适用于新会话、已有会话、普通回复与流式回复。以自然、耐心、平等协作的方式陪伴学习，不沿用历史中的初中教学老师身份，不新增固定自我介绍或欢迎台词。`ASSESS_SYSTEM` 仍只负责内部评价，不承担对话角色。修改角色无需改变 Provider 或 API 合同；重启后端后，下一次生成即使用新提示词，历史消息保留原文。

开场不复读固定欢迎语；回答用户提出的真正问题；通常一两个短段，按需代码/完整解释；一次一个学习目标，不每轮都安慰、反问或罗列选项。答对可以接着练，答错且情绪未知则正常解释；正确但紧张则保留正确反馈并放慢。思考时等待；明确暂停、结束、拒绝会执行实际控制，不只口头答应。

手动提示和课内文字请求是输入意图，不是选择固定回复；示范、继续和换例子可直接用普通文字表达。常驻回复动作组已移除，思考/帮助/纠正仅在符合门控的主动支持卡内出现。结束/暂停等按钮始终保留，可立即取消网络请求；文字控制需要模型先识别，有模型延迟。

## 上下文与隐私

最近最多24条完整消息、最多20000字符；超出后丢弃最旧上下文，不宣称无限记忆。当前私有题目只给评估器，生成器只看可见问题；完整示范请求才提供reference。历史中的旧答案已经展示过，可以正常回看。没有把未来题库、API密钥、音视频、草稿或人脸关键点送给生成器。

评估记录保存到服务器assessment_log用于审计，不展示为确定的心理测量或置信分数。公共导出不包含私有rubric/reference和完整learner_state；只包含有限、可过期、标注自述来源的camera_alerts。删除会话连同其JSON状态一起删除，第三方日志不受本接口管理。

## 调整方式

- 改课程内容和主题范围：courses.py；保持目标ID稳定，重大变动升级DIALOGUE_VERSION。
- 改人性化语气、长度和教学行为：REPLY_SYSTEM；不要写台词库。
- 改状态抽取：ASSESS_SYSTEM + TurnAssessment；用带否定、引用、反讽、模糊和纠正的样本评估。
- 改时效和历史容量：dialogue.py常量，并同步隐私说明与费用估计。
- 改模型服务商：模块04/11；改交互样式：模块01。

## 验证与未验证项

`tests/test_dialogue.py` 验证课程和历史投影、参考答案隔离、无证据降级、纠正/过期、正确与压力独立、未知不等于负面、错误序列中断、动态换题、自然语言控制、生成取消和旧会话迁移。

自动化使用tests内替身，不衡量真实模型的教学能力。本轮未使用真实第三方密钥测试。接入后至少逐个测试：三个课程的正确/错误/理由不足；“还行吧”；答对但紧张；答错但开心；“其实我没紧张”；“我只是在想”；要求换生活例子；要求完整答案；离题与提示注入；暂停/结束。人工核对自然度、事实、题干与判据一致性，并记录成本和延迟。课程语义约束主要依赖提示词与模型，结构校验不能保证所有输出不越界。

## 疲劳/信息负荷自述与摄像头提醒

TurnAssessment新增fatigue和cognitive_load，默认unknown。fatigue=present/absent/unknown；cognitive_load=high/manageable/unknown。只允许用户当前自身明确自述，必须逐字引用本轮文字；引述他人、假设、否定、单次错误、停顿、皱眉或压力高都不能单独成为标签依据。否定需给absent/manageable清除旧状态；普通纠正与按钮纠正均优先。没有API时不会推导这些标签。

learner_state沿用300秒/3轮时效；这两项不从task_answer补成已知。明确疲劳或过载时response_policy.reduce_information_load=true，生成器仍按课题自然减少同时信息量，不诊断、不改变事实评分。原认知、效价和压力维度保持独立。

camera_alerts(s)只向当前访客投影kind、source、evidence_quote、captured_at、expires_at，不投影其他内部状态。仅active/support=on且有同意时显示，暂停/结束/过期/纠正后消失；unknown和无验证视觉来源不显示。此字段仍表示用户反馈。原仓库60秒有效基线和启发式阶段已另经WS接入，视觉提醒不混入持久化自述，前端以独立来源和暂定措辞合并显示。

相关测试涵盖显式自述、过期、3轮时效、支持暂停、错误/压力不误触发、纠正清除、未知来源拒绝以及端到端公共API投影。

模型回复可另给visual_judgment：基于当前有效视觉线索、近期对话和自述独立选择possible_fatigue/possible_overload/no_concern/uncertain；未校准或无效时强制null。该结果只在同一run与有效观测片段内短期使用，旧解释不再作为原始证据送回模型。自述否认疲劳/过载优先，模型应自然询问或放慢，不照抄固定话术或把行为阶段当诊断。

SSE通道不改变两阶段评估与视觉快照：用户消息先保存，本轮history排除该条以免重复；生成阶段只流式输出顶层reply，最终仍验证DialogueReply再提交。纠正也可在先保存后走流式承接；协议、失败与取消见模块15。

题干宽容性：删除逐字匹配的硬拒绝。实际回复与内部摘要不同也会显示，评分问题绑定到实际文字；参考答案适用性由现有评价器按语义确认，不能用固定关键词、相似度阈值或另一道题的判据判断用户。具体字段与修改入口见模块02。

自适应支持卡：模型依据 proactive_context 和最近课内交流生成 support_title/正文，先理解当前状态，再给有温度的支持及一个可执行建议。没有固定检测开场或模板句库；仅视觉时保留可能/迹象含义，理解卡点不诊断为认知障碍。支持可直接给单步 hint 并计为已获帮助；禁止完整答案和新题。有效状态变化通过原卡后台重写，普通输入继续保留卡片，详见模块05。

状态说明的产品表达：普通回复、提示和支持卡默认只用一句自然的“可能有些疲劳/负担可能偏高/这一步可能卡住”等自由表述，不展开检测过程或指标。保留不确定含义，随后继续具体、有温度的支持和解决建议；用户主动问依据才简洁解释。内部判断、视觉上下文和自述优先规则保持原实现，不用文本过滤器截断模型建议。
