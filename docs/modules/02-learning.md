# 02 · 课程与自由对话状态

## 职责与边界

`study/courses.py` 保存三个主题的范围、学习目标、事实约束和允许的误区标识。这里没有可见欢迎语、题干或提示台词，也没有强制六步顺序。

`study/learning.py` 只处理状态：创建空会话、应用控制、提交真实模型结果、记录练习证据、升级旧会话。`study/tasks.py` 的旧题库仅供历史会话兼容与课程目录使用，不再生成新会话中的任何消息。模型策略和状态上下文见模块12。

## 当前行为

- 创建会话返回空消息；页面调用 `turns(event=open)` 取得真实模型开场。未配置 API 时展示配置入口，没有预设题目。
- 模型在当前课程的目标内决定解释、追问、提示、示范、练习、等待或转回课题。用户可以直接提出问题、要求简短解释或改变课内讨论方向。
- `focus_id` 为正在讨论的目标，不是固定进度。模型可在反馈后自然引入新练习，无需“继续”按钮解锁。
- `exercise` 在服务器保存当前可评价练习的 prompt/reference/rubric/id；只有可见回复进入前端。允许题干概括和自然改写，不要求逐字包含；实际可见回复是评分问题的依据。
- 提示、完整示范、继续探索、换例子都调用模型。完整示范可直接主动选择；普通对话中明确要求示范也由意图识别处理。
- 无固定步数、无强制感受提问、无自动结束；用户结束后查看事实性学习记录。

## 练习记录

已提交回答有 supported 证据时，当前练习最多记一次：`completed_independently`、`completed_with_hint` 或 `reviewed_after_example`。最后一种不能统计为独立完成。换例子记录 skipped。记录是本次练习的模型核对结果，不是经过验证的掌握度评分。

提示计数来自按钮请求或模型声明的 assistance。新练习重置当前提示/曝光标记。模型会自行生成题目和内部判据，正确性还需接入后的评估；不能把合同单测当作教学质量认证。

## 会话兼容

新会话 `content_version=dialogue_version=course-dialogue-v1`。旧会话的 content_version、原消息、进度记录与授权记录保留；读取时惰性投影，下一次写入才保存新增字段。旧当前题转成私有 exercise，后续改用自由对话。不会删除旧脚本消息，也不会修改过去的答案曝光记录。

## 修改点与验证

改课题范围：courses.py；改学习记录：commit_dialogue；改迁移：ensure_dialogue；改语言风格或状态适配：模块12。不要把课程题干再写入 React 或 new_session。

运行 `npm run test:api`。覆盖空开场、模型生成提示、换例子不算完成、自动接续、答案曝光、旧记录迁移、幂等与取消。真实模型的事实正确性和自然度待接入后验证。

## 自然例子与可见问题（2026-10-30）

不再因为exercise.prompt与reply字面不同而拒绝整段回复，也不把内部题干强行拼到可见文字上。exercise_from_reply在两者未逐字对应时，将实际reply绑定为exercise.prompt，原摘要保留为仅服务器可见的metadata_prompt，并标reference_alignment=unverified。

下一次内部评估按语义核对例子/条件/问题，可通过evaluation.reference_applicable=true确认参考答案适用，正常进行评价；false或未知时只保留自然对话，不把该参考答案用于对错、独立完成或示范引用。此判断复用已有评估调用，没有新增模型请求。既有逐字对应与旧会话继续兼容。

replace但缺少练习元数据时改为clear，不伪造题目或阻断说明；keep/clear附带多余exercise时忽略。课题范围、用户控制、私有判据隔离与最终版本检查继续生效。
