# AI 学习助手：线上部署

本目录属于 GitHub 仓库 `fft020205/ai-study` 的 `railway-production` 分支。`main` 保留本地开发方式；生产分支合并主线修复并包含登录与托管配置。源码不包含原 `.env`、`data/`、学习记录或真实密钥。
新增账号、登录、持久化登录会话、每位用户与全站每日模型调用限制；保留原 Next.js/FastAPI、课程、SSE、摄像头与原视觉引擎。

线上服务：https://ai-study-production.up.railway.app ，项目 `AI Study` / `production` / `ai-study`。现有 `/data` 卷保存账号与记录，升级沿用该卷和既有秘密变量。

## Railway 配置

1. 对现有服务使用 `railway-production` 分支；仓库根目录包含 `Dockerfile` 和 `railway.json`。优先连接 GitHub 分支；若平台无仓库读取权限，可从该分支检出目录使用官方 CLI 上传，不要另建服务。
2. 绑定**持久卷 `/data`**。固定一个副本，API 固定一个 worker。重启会清理进行中的生成和视觉校准，已保存记录和账号由持久卷保留。
3. 生成服务的 HTTPS 公网域名。`RAILWAY_PUBLIC_DOMAIN` 由平台提供；使用自定义域名时设置 `PUBLIC_URL=https://实际域名`，仅允许精确的同源地址。
4. 在平台服务变量中设置下表参数，密钥使用秘密变量，不放入源码或浏览器。升级时保留平台已有秘密变量，不从本机文件重新复制或覆盖。
5. 发布服务，等待 `/api/health` 健康检查成功。确认公网注册、登录、真实对话、SSE、退出后拒绝访问、两账号隔离和重启后记录恢复，再向其他人提供链接。

| 变量 | 内容 |
|---|---|
| `AI_BASE_URL` | 已有服务商的 OpenAI 兼容 API Base URL |
| `AI_API_KEY` | 已有模型密钥，秘密变量 |
| `AI_MODEL` | 服务商模型标识 |
| `AI_TIMEOUT_SECONDS` | 默认 45 |
| `PUBLIC_URL` | 自定义域名时填写完整 HTTPS origin；平台默认域名自动读取 |
| `REGISTRATION_ENABLED` | 默认 true；false 关闭新注册，已有用户仍可登录 |
| `AI_DAILY_CALLS_PER_USER` | 默认 100 次上游请求/用户/UTC 日 |
| `AI_DAILY_CALLS_TOTAL` | 默认 1000 次上游请求/站点/UTC 日 |
| `PORT` | 平台提供；本地容器默认 8080 |

启动器强制 `AUTH_REQUIRED=true`、`COOKIE_SECURE=true`、`AI_SETTINGS_ENABLED=false`、`AI_PROVIDER=openai`，按域名设置 `ALLOWED_ORIGINS`，数据库固定在持久卷，禁止读取本机 AI 配置文件。缺少域名、密钥、模型或持久卷时拒绝启动，避免发布一个看似成功但没有可用 AI 或持久化的页面。

## 访问和数据

- 访客自行注册用户名和至少 12 位密码，登录后使用站点统一配置的模型。现有主界面保持原样。
- 账号密码使用带随机 salt 的 scrypt 哈希；14 天登录令牌只在数据库保存 SHA-256，浏览器 Cookie 为 HttpOnly/Secure/SameSite=Strict。
- 学习记录归属由服务端账号决定，跨浏览器登录同一账号可恢复已保存记录。不会将原浏览器匿名访客记录自动归给新账号。
- 全部学习 API、导出、删除、重命名和视觉 WebSocket 都校验身份。退出会撤销当前登录令牌，并取消该账号正在生成的回复和视觉连接。
- 普通用户没有接口配置权限，页面与接口不返回密钥。密码验证错误不回显密码。
- 登录每个用户名 15 分钟最多 10 次尝试，全站每分钟最多 120 次；注册全站每小时最多 10 次。限额存库，重启不清零。
- 每次真实上游请求前以数据库原子事务占用用户与全站额度，包括内部核对、回复、SSE 与主动支持；请求失败也计数。并发不能超支，额度按 UTC 日重置。
- 次数上限不等同于金额上限。实际费用和服务商余额由模型服务商计费；可在其后台另设预算。
- Nginx 直接转发产品 API，关闭 SSE 缓冲、支持 WebSocket Upgrade、限制请求体 64 KiB，API 不直接监听公网。
- 原始音视频与人脸关键点继续留在浏览器；派生行为特征改为送到托管的产品后端内存，必要摘要随真实模型调用发送给配置的模型服务商。部署界面会明确说明这一点。

## 当前边界

这是小规模多人试用部署：一个服务副本、一个 API worker、持久化 SQLite。不要增加 worker 或服务副本数量；横向扩容需要改造共享撤权、视觉状态、取消任务和数据库。

账号暂不支持邮箱验证、密码重置、SSO、账户删除和管理后台。学习记录仍可按原产品功能导出和删除。卷备份和恢复需要在平台侧配置和验证。

构建使用固定依赖与视觉资源哈希，不包含真实密钥或学习数据。Docker 镜像由 Railway 构建，必须等待新部署成功并核验公网健康与登录门控；不能把本地测试通过或触发构建当成发布完成。

## 更新流程

从最新生产分支合并 `main`，运行测试和生产构建，扫描暂存区不含秘密与数据库后提交到 GitHub。部署前核对只有预期的服务变更，保持单副本、`/data` 挂载与平台变量。`deploy/release.json` 记录合入的主线提交与前次部署；实际运行提交以 Railway 部署元数据为准。2026-11-09 此次合入 `7007058`，修复视觉短暂断线导致答题/AI 回复被完整校准中断。
